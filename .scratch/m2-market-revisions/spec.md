# M2 還原行情來源明示的更正與撤回

**Parent:** [P2-04](../../docs/DEVELOPMENT_BACKLOG.md#p2-04修訂與撤回) · [正規化 ledger 已支援的範圍](../m2-price-history/issues/02-revision-ledger.md)

**Status:** needs-info（工程與兩市場既有行情重播已驗，待真實行情通知原件）

## Problem Statement

行情保存在獨立 SQLite 資料庫。來源若對某日、某股、某項已保存的行情明示更正或撤回，研究者需要查到原值、通知及它們當時何時可得。一般日檔缺列無法作為撤回依據。

## Solution

在原行情研究路徑接受與來源及特定原件綁定的私有通知，依當時已知的期間輸出有效觀察及通知證據。保留既存研究版本、原始快照與既有定義，使提醒、研究事實及事件讀者能回查原版本。

## User Stories

1. 身為研究者，我要回讀通知進入本地系統前後兩個時點，以核對當時可採用哪個版本。
2. 身為審閱者，我要查回特定市場、股票、交易日、欄位定義、原件與更正通知，以防不同來源或其他級別交易的值混用。
3. 身為維護者，我要區分原檔缺列、晚到舊檔與正式撤回，以便保全早期資料與正確重跑。
4. 身為研究者，我要保留已保存版本的首次事件基準，以便重讀先前報告與當時的限制。

## Implementation Decisions

行情來源、研究價格基準及市場單位沿用已確認決策。原行情未記錄本地登錄時間的資料維持未知；新增通知的首次本地登錄由系統實際產生。有效／公告時間與觀察／登錄時間分列，恢復狀態時檢查目標版本、通知、替代原件與適用範圍。對缺少正式通知的來源，揭露可驗到的狀態。

## Testing Decisions

使用兩市場原有的私有行情 CLI、研究、audit 與既有事件讀者。合成中以真實 SQLite、原始 bytes、早／晚截止與已保存的資料驗證更正、撤回、重發、範圍錯配、同時衝突與冪等。以原兩日真實資料在副本重讀。真實通知須有官方原件明示原快照、個股、交易日及替代／撤回行為；單純同日不同表示或數字不同不能取代通知。

## Out of Scope

猜測正式行情單位、覆寫既存檔案、將股價變化用作總報酬或新增投資訊號。
