# M5 手動維運、容量與私有研究復原

**Status:** ready-for-agent

## Problem Statement

單一 SQLite 備份不足以重播一個研究版本。維護者還需要原始證據、設定、ledger、各 bundle 與其引用。手動串接命令時也難以判別哪一階段失敗，或現有磁碟與模型是否承受下一批工作。

## Solution

提供唯讀容量報告、整組備份與驗證還原、固定負載的效能量測，以及可逐階段重跑的私有更新入口。每項交付可用已有資料或合成資料單獨驗證。整體復原驗收須在實際獨立環境執行。

## User Stories

1. 身為維護者，我要找出超限的目錄與增長來源，以決定私有儲存配置。
2. 身為研究者，我要列出封存版本的所有來源引用，以便重讀歷史。
3. 身為維護者，我要從一致資料重建完整目錄，以在新位置執行同樣的 audit。
4. 身為維護者，我要重跑失敗階段，以保留仍可讀取的最後成功版本。
5. 身為研究者，我要得知報表期別與交易日，以辨識來源是否到齊。
6. 身為維護者，我要量測實際的精確搜尋成本，以決定可用的樣本規模與預算。
7. 身為接手者，我要區分本機還原與跨裝置復原的證據，以確認仍需執行的步驟。

## Implementation Decisions

沿用既有 SQLite 備份及私有路徑保護，以新目的地及逐檔驗證支援整組封存。手動更新需等 audit 成功才將候選提升為最後成功版本；重試沿用已驗、未受損的證據。盤點與封存計畫採唯讀，真正刪除仍需保存政策與授權。

## Testing Decisions

每票透過對應的使用者 CLI 重跑，使用真實臨時 SQLite、原始 bytes 與已知檔案大小的 fixture。復原後走原 bundle audit、事件統計與來源讀者。效能報告保存量測條件、原始計數、流程時間與環境。真實資料及量測原始輸出放私有位置。

## Out of Scope

排程、外部通知、公開金融資料、刪除歷史、額外主機採購。
