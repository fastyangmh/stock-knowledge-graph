## Problem Statement

研究者已有合成資料驗證的私有流程，但尚不能確定鎖定的目標環境、真實模型、官方全檔、幣別／尺度／時間及實際瀏覽器能共同正常運作。已有數值差異工具不等於取得獨立參考資料；模型／HTTP fixture 也不能證明真實服務可用。研究者需要可重現的證據與明確受阻狀態，才能信任第一批真實私有研究產物。

此外，事件工具讀取展示圖數值，畫面上限可能改變可分析事實。這個缺口可先用離線資料改善，但不能用工程完成替代真實來源、完整時間與市場歷史驗收。

## Solution

讓研究者用明確股票代碼，在 Linux／Python 3.11 鎖定環境手動完成官方來源到私有 bundle 的流程。每個來源保存取得證據與欄位契約；抽檢以獨立原始公告或官方查詢作參考；只有證據支持的尺度才轉成可比較定義。三個私有頁面使用真實本機 HTTP 驗收，圖譜另核對原固定 CDN 與只讀 Pages 示範。

每次驗收提供候選 Commit、環境、設定、命令、exit code、資料範圍、證據 hash、結果及未驗證項。M1 完成表示這條基礎路徑有真實證據；完整私有研究由後續里程碑補足。

獨立預備線另建立不可變的未裁剪研究數值契約及新版事件讀取路徑，保留舊 bundle 與首次保存語意。

## User Stories

1. As a 私有研究者, I want 使用明確股票代碼開始研究, so that 我不必等待指數名單且不會被誤標為成分股。
2. As a 開發者, I want 在 Linux／Python 3.11 依 lock 重現環境, so that 舊環境測試不會被當成目標環境驗收。
3. As a 維護者, I want 同時核對兩處 dev 依賴與 lock, so that 只有必要的相容修復才改變依賴。
4. As a 研究者, I want 固定真實模型 revision 與權重識別, so that 語意結果有可重現的模型身分。
5. As a 研究者, I want 首次編碼與後續快取都有證據, so that 我能區分真實模型執行與測試 encoder。
6. As a 研究者, I want 同資料重跑不載入模型也不掃配對, so that 已保存的向量與關聯確實被重用。
7. As a 研究者, I want 改一篇文本只重編該篇, so that 更新成本隨實際修改而變。
8. As a 研究者, I want 只改股票映射時重建關係而不重編文本, so that 股票證據正確且不浪費模型工作。
9. As a 資料核對者, I want 保留來源實際回應 bytes、時間、URL、內容型態與 hash, so that 每筆研究輸入可以追溯。
10. As a 資料核對者, I want 看見全檔欄位、列數與日期分布以及選股覆蓋, so that 選股成功不會遮住全檔格式異常。
11. As a 研究者, I want 403、HTML、缺欄位及混合交易日停止該批, so that 我不會看到假成功或被改標日期的資料。
12. As a 研究者, I want 部分來源失敗保留舊成功版本並產生失敗報告, so that 我可以辨認失敗而不失去先前研究。
13. As a 研究者, I want TWSE 與 TPEx 的來源及股票分別驗收, so that 市場資料不被混用。
14. As a 研究者, I want 公司／月營收與行情都通過真實 SQLite 和 bundle audit, so that 單獨 parser 通過不會掩蓋整合錯誤。
15. As a 財務核對者, I want 以獨立公告或財報數值準備 reference, so that 抽檢不只是同一輸出的自我比較。
16. As a 財務核對者, I want 單位、幣別、報表範圍、期間與公告／觀察時間明確, so that 看似相同的數值不會被錯誤比較。
17. As a 研究者, I want 未知尺度保持 source_reported 並顯示不可比較, so that 缺少證據不會變成自行換算。
18. As a 研究者, I want 新尺度版本不改寫既有研究, so that 歷史結果可以照原定義重讀。
19. As a 核對者, I want 零筆、差異與不可比較都不算抽檢成功, so that 成功狀態代表確實比較過。
20. As a 行情核對者, I want 核對成交股數、張數、價格、成交值及交易範圍, so that 欄位名稱不會被當成已驗證尺度。
21. As a 使用者, I want 真實瀏覽器以固定 CDN 顯示圖譜並檢查 bytes 雜湊, so that 錯版圖檔被拒絕。
22. As a 使用者, I want 手機、快速切換、空結果與失敗後恢復可用, so that 畫面不會顯示過期選擇或殘留結果。
23. As a 使用者, I want 來源文字安全呈現且私有 HTTP 僅提供允許資產, so that 瀏覽研究不會暴露 DB 或原始證據。
24. As a 研究者, I want 歷史比較與事件頁透過真實 HTTP 載入, so that 記憶體 fetch 的成功不會掩蓋部署行為。
25. As a 審閱者, I want 真實、合成、受阻與未執行各自列明, so that 測試數量不會被誤認為金融驗收。
26. As a 研究者, I want 未裁剪數值獨立於展示圖保存, so that 改節點上限不會改變研究分母。
27. As a 研究者, I want 新數值契約保留來源、時間、單位、schema 與證據 hash, so that 我能理解何時保存了哪個事實。
28. As a 研究者, I want 舊 bundle 可讀並標明展示範圍限制, so that 系統不假裝補回未保存的資料。
29. As a 研究者, I want 新分析版本仍凍結首次保存基準與首次後續值, so that 較晚修訂不會回頭改結果。
30. As a 維護者, I want 超額、篡改、未知 schema 與新舊混合分析明確處理, so that 系統不靜默截取樣本或退回較窄資料。

## Implementation Decisions

已確認、不再重問的決策：

- 使用 Linux／NAS／Server、本地 SQLite、uv lock、既定多語 Sentence Transformers、Cytoscape 與 main/root Pages。
- 盤後手動執行；自選股票不推論指數歸屬；價量／營收提醒分開；量化維持 A 描述統計。
- 原始證據與研究產物保持私有；未知金額尺度不轉換，缺值不補零；不以來源日期代替本地保存時間。
- 保留既有成功 pointer、不可變 bundle 與發布邊界。

以下為本次待確認的實作提案：

1. **環境與模型。** 重用 local.check 與 research／semantic 入口；真實模型測試是 opt-in 驗收，不放進必須離線的預設 check。模型使用完整、不可變 revision；不以 main 或浮動 tag 取代。缺少可用網路或已校驗快取時標記受阻。
2. **證據契約。** 擷取報告含來源識別、HTTP status、Content-Type（來源未送時明示 missing）、時間、實際 URL、bytes／SHA256、欄位／列數、日期分布、指定股票覆蓋、成功／失敗階段、錯誤分類。安全保存有界失敗回應，不能將 HTML／403 保存為成功金融快照；超大回應記錄截斷狀態，不偽稱完整 hash。
3. **批次行為。** 公司／營收保持整批成功才更新成功指標；行情保持每市場批次。必要格式修復先加最小失敗回歸，再實作；不在此次另建通用排程器。全檔的欄列／日期檢查與選中列數值檢查分列。
4. **日期契約。** 交易日必須全檔符合預期日期。公司出表日、營收資料年月與取得日是不同維度；記錄分布，依查證的來源契約拒絕不允許的混雜，不能要求所有維度等於今天，也不把 expected-date 當歷史查詢。
5. **市場邊界。** M1 使用分市場研究 run，沿用單一 price_market 入口。預設公司／營收驗收從已啟用 TWSE 開始；TPEx 行情串接需合法且獨立核對的上櫃財務輸入。若啟用既有 TPEx registry 來源，先驗證其條件與實際欄位，不能從 disabled 推論已可用。
6. **尺度與相容性。** 逐來源查證後發布有版本的正規化定義，保留原始數字／尺度／幣別與轉換依據。舊快照／bundle 不就地升級；需要新結果就重新產生新版。所有讀者包含 market_graph 的 raw 重建檢查、提醒、financial_review、event 可比較鍵同步尊重版本。明確對應 statement_scope／report_basis 與現有 consolidation／value_basis；有衝突就拒絕，不忽略。
7. **抽檢門檻。** 每個驗收市場至少兩檔、實際可得的一個期別／日期；每個宣稱支援的數值欄位有至少一筆獨立參考。預設誤差 0。參考資料有其原始定位、日期／版本及證據 hash，不能從被測產物衍生。季度單季／累計等不適用項標記未涵蓋，季度全量適配留 M3。
8. **財務與行情核對分開。** 財務重用 financial_review；行情不硬塞成月營收指標，以同等嚴格的私有核對報告列來源、單位、交易範圍與差異。
9. **瀏覽器。** 圖譜讀實際本機 HTTP，原 CDN 以真實 HTTPS 載入並記版本／資產 hash；歷史與事件頁連實際本機 server。故障案例可在測試 server 回傳錯誤／延遲 bytes，成功路徑不得替換 window.fetch。CDN 封鎖就如實受阻，不能改生產 CDN 或瀏覽器政策。只讀 Pages demo 另列，私有資料不送 Pages。

P2-01 獨立預備線提案：

10. **唯一高層契約。** research 在展示裁剪之前生成新版本的不可變研究事實集合，audit 驗證後交給 event。事件工具只讀已稽核 bundle，不查 SQL／不重新下載；不增設對外完整事實 API。
11. **事實範圍。** 所選股票、known_at 範圍內 replay 得到的全部財務／既有籌碼數值，以及指定市場截至 trade_date 的本地已保存、可讀取且證據驗證的行情歷史；不沿用提醒的前 20 筆或展示節點上限作研究裁剪。來源衝突延用拒絕策略；沒有行情輸入則明示未含行情。未擷取歷史不補出，容量超限整批失敗。
12. **版本與 provenance。** 契約包含 schema／producer／研究範圍、stock／source／metric／period、value／unit／currency／scope／basis、可得／觀察／本地登錄時間與各時間語意、正規化與 raw 證據引用。已知欄位逐值保存；行情缺本地 recorded_at 時明示 unknown，不能用 observed_at 代填。bundle completed_at 僅代表本次保存時間；完整歷史登錄遷移由 P2-04 負責。
13. **稽核與預算。** 新檔加入 report hash、audit 檔案清單、總量／筆數上限與捕捉 bytes 的一致性驗證；未知 schema、檔案缺漏、混入其他股票、未來時間、篡改、symlink 與超額拒絕。既有 256 MiB bundle 預算與 32 MiB JSON parser 上限先保留，超額明示；不為標榜未裁剪而繞過預算。私有 server 不提供 raw／DB／完整事實檔。
14. **事件分析相容性。** 有新契約就必須使用並驗證，損壞不能退回 graph。純舊 bundle 可走原分析版本並標明 display_graph_only；新契約採新的分析版本。混合目錄需明確選擇／揭露各 cohort，新版計算不把舊圖補作完整事實，也不靜默丟掉舊版；報告列納入／未納入及原因，跨範圍不合併分母。首個新版 bundle 不回填為舊事件當時的完整基準。
15. **研究定義。** 首次保存事件與首次後續值、1／5／20 筆觀察及1／3／6曆月保持原義；範圍變更以分析版本區分，不重命名為交易日、不採最終修訂值。事實 ID／provenance 不依賴展示 node ID 是否仍存在。

## Testing Decisions

- 好測試證明外部可見結果：私有原始 bytes 與 hash、正規化數值、DB 可重讀、bundle audit、報告分母、CLI exit code、瀏覽器狀態及失敗後舊成功版本不變。避免測試內部迴圈／SQL 字串或鏡像實作。
- 首選同一條 CLI 到私有產物的端到端介面。沿用 official adapter／market prices／research／event integration 的真實臨時 SQLite 先例；外部 HTTP 在離線回歸用受控邊界，live 驗收另記。
- 語意測試沿用既有 encoder seam；合成與真實模型分開記錄。首次編碼、全快取、單文件、映射四情境檢查 encoded、pairs、向量與關係結果；全快取再驗證 loader 不被使用。
- 財務沿用 financial_review 的相同定義、unknown unit、零筆、差異／容許誤差測試。尺度修復須覆蓋 raw→新版正規化→research→audit→比較／事件的可見相容性。
- 瀏覽器重用三個 smoke harness 的案例，但以實際 server／傳輸跑完整成功路徑。涵蓋三頁桌機與手機、WebCrypto、惡意來源文字、快速切換、空狀態、404／錯版／損壞與恢復。
- P2-01 建立超過展示上限的固定輸入，改兩組展示政策後比較完整事實、事件總數、各狀態分母與結果；排除 run ID／完成時間等識別差異，不要求整份 bytes 相同。測試固定語意時間，並驗證稍晚修訂不回寫基準。
- P2-01 覆蓋新／舊／混合版本、未知 schema、雜湊缺漏、超大檔、超筆數、未來／晚到資料、未知時間、跨股混入、無樣本及 private HTTP allowlist。舊限制須在 JSON 與使用者畫面均可見。
- 產品修復遵循 TDD：先記錄相關失敗，再最小修復；完成執行 local.check，前端變更加 frontend 與適用真實瀏覽器驗收。文件修改檢查連結與 diff。
- 每票存實際環境、Commit、命令、exit code、資料種類、hash、結果與剩餘限制；未執行不列 passed。pytest／unittest 同一套測試不相加。

## Out of Scope

- 本輪規劃不直接實作；確認後逐票推進。
- M1 不新增季度／籌碼／公告適配器、權威日曆、公司行為還原或完整撤回 ledger。
- P2-01 預備線不重建未保存歷史、不補行情 recorded_at、不改研究目的或提醒門檻。
- 不改成跨市場單一 research run；不另造大型 ETL／排程框架。
- 不公開真實金融資料、不外開私有服務、不啟用自動排程／push、不付費或簽約、不清除歷史。
- 不重選股票池、不等待名單、不做策略 B、交易成本、買賣／勝率／alpha 或因果宣稱。
- 不把一次下載或一筆抽檢當作每日穩定、全市場覆蓋或投資有效性證明。

## Further Notes

本輪尚未執行產品驗收。所有舊測試數字只適用其原版本；本規格不宣稱新版已通過。
