# 研究提醒：價量與月營收各自呈現

[文件中心](README.md) · [私有研究流程](PRIVATE_RESEARCH.md) · [驗證紀錄](VERIFICATION-2026-11-16-ALERTS.md)

## 決策與範圍

2026-11-16 使用者選定 C：同時提供價量及月營收提醒，**分開呈現、不合併評分、不產生買賣指令**。第一版為明確規則引擎，不是報酬預測、完整歷史回測或統計顯著性檢定。門檻只是可調整的工程起點，尚未以真實投資績效校準。

`local.research --alerts` 以現有研究ledger的「當時本系統已知」財務資料，以及驗證過原始CSV的同來源報價計算。沒有加此旗標時維持原流程；不下載資料、不下單、不使用券商憑證、不修改公開 `data/` 或安裝排程。

## 第一版規則

| 類別／規則 | 公式與預設觸發條件 | 最低需要 |
| --- | --- | --- |
| 收盤價觀察變動 | `100 × (本筆收盤 / 前筆已觀察收盤 - 1)`，絕對值 ≥ **5%**；保留正負號 | 同來源2筆有效正數收盤 |
| 成交股數相對基準 | 本筆成交股數 / **前20筆觀察**平均成交股數 ≥ **2倍** | 共21筆觀察；本筆不進基準 |
| 月營收年增率 | 來源提供的最新期年增百分比，絕對值 ≥ **30%** | 最新期年增率，單位為percent |
| 月營收月增率 | 來源提供的最新期月增百分比，絕對值 ≥ **20%** | 最新期月增率，單位為percent |
| 年增率較前月變化 | 最新年增率 − 上月年增率，絕對值 ≥ **10個百分點** | 同來源2個連續月份 |
| 年增率連續變化 | **3次**連續月間變化皆 > 0，或皆 < 0 | 同來源4個連續月份的年增率 |

**「年增率持續上升」不等於「營收正成長」。** 例如年增率從 -40%、-30%、-20% 到 -10% 會觸發上升研究提醒，但仍然是負成長。平盤不算同方向連續變化。

目前沒有權威交易日曆連續性驗證，價格是「相鄰已觀察報價」比較；前20筆**不能宣稱為連續20交易日**。任一比較所需相鄰觀察間隔超過預設10個日曆日，會標記不可比較。未還原價格可能受除權息、拆併股或尺度變更影響；本模組不校正公司行為，不把價差當投資總報酬。

## 缺漏、修訂與證據

每條規則都輸出一種狀態：`triggered`（達到門檻）、`not_triggered`（已算但未達門檻）、`insufficient_data`（資料不足）、`not_comparable`（不可比較）。後兩者不是「沒有異常」。

- 價量基準不含目標當天；缺少目標報價不以昨天資料替代。零成交股數可是真值，但歷史平均為零時不輸出無限倍數。零／缺失收盤不計算價格變化。
- 只使用截止時間前可得的修訂；未來觀察與較晚本地登錄的財務資料不進計算。行情歷史沿用既有 `observed_at` 與原始快照稽核；它不是完整的市場公告時間資料庫。
- 每筆行情重新使用 `market_graph.read_prices` 的來源、OHLC、日期、校驗碼與原始CSV驗證。單一讀取有100,000筆修訂上限，依window與最大間隔限制日期範圍；不查API。
- 最新營收期間已存在但該期年增率缺漏，不偷偷改用前一期的百分比。連續月份缺口不插值。
- **只分析來源已提供、單位明確為percent的年增／月增率。** 未核對金額倍率的 `source_reported` 不重算成長率；不混合不同來源的月份。這不保證來源百分比本身一定正確，仍需實際資料抽檢。
- 每條規則保留公式、門檻、資料期別、比較基準、來源URL、觀察／可得時間及適用的原始／正規化快照SHA256。內容ID由輸入證據、設定、版本與截止時間產生，不作數位簽章或授權證明。

## 操作方式

先完成[私有研究流程](PRIVATE_RESEARCH.md)的公司／月營收快照正規化，以及需要的行情累積，再執行：

```bash
uv run --locked python -m local.research \
  --input local/private/normalized-watchlist.json \
  --symbols 2330 2317 \
  --history-db local/private/research-history.db \
  --output-root local/private/research-runs \
  --prices-db local/private/market-prices.db \
  --price-snapshots local/private/market-prices \
  --trade-date YYYY-MM-DD \
  --alerts
```

`YYYY-MM-DD` 是資料實際交易日；代碼只示範參數，不是指數名單或推薦。沒有行情時，可略過全部3個行情參數；月營收繼續評估，價量顯示缺少輸入。研究提醒與 `--analysis none|lexical|semantic` 獨立，不把提醒、股價或營收數字送進文字Embedding。

成功版本會新增私有 `alerts.json`；每檔圖譜的可選 `research_alerts` 欄位只帶該股結果，含兩個獨立類別。原圖SHA256已涵蓋這個欄位，既有檢查與本地預覽可直接使用。`report.json` 記錄提醒檔SHA256、完整設定與各類觸發數；沒有綜合分數。失敗不替換上一個成功版本。

```bash
uv run --locked python -m local.preview \
  --data-dir local/private/research-runs/<成功run-id>/data \
  --port 8765
```

瀏覽器在圖譜下方分別顯示「價量提醒」「月營收提醒」，展開即可看公式與證據。舊圖未計算提醒時顯示「尚未計算」，不猜測狀態；切股失敗或空清單時清除上次提醒，避免錯股顯示。

## 可調設定

在私有JSON檔提供需要修改的欄位，再加 `--alerts-config local/private/alerts-config.json`；未指定的欄位採預設。未知欄位、布林代替數字、NaN、非正門檻與超出限制的window會拒絕執行。

```json
{
  "price_change_pct": 5.0,
  "volume_window": 20,
  "volume_ratio": 2.0,
  "max_observation_gap_days": 10,
  "revenue_yoy_pct": 30.0,
  "revenue_mom_pct": 20.0,
  "revenue_yoy_change_pp": 10.0,
  "revenue_trend_steps": 3
}
```

更改門檻會產生新的研究結果與設定紀錄，不修改舊版本。這些參數應以未來資料驗收與研究評估調整，不能把本次虛構測試當作有效選股門檻。

## 未完成與安全界線

沒有真實績效校準、即時推播、交易訊號、下單、公司行為還原、正式交易日驗證或官方資料live驗收。測試只證明指定條件下的工程行為；公開使用權仍按原有審查流程處理，不能因為數值變成提醒就推論可公開。各類提醒的資料期間、來源與不足狀態都應保留，不挑出觸發結果冒稱完整評估。

## 跨版本提醒比較

現在可透過[研究歷史](RESEARCH_HISTORY.md)比較兩個已儲存版本。只有同規則與相關設定、同來源定義、前後皆可評估的結果，才會標示新達或未再達門檻；資料缺漏、首次可評估及股票範圍變更另外標記。新版價量證據增加market／price_unit／price_basis，舊報告未保存時不猜測比較基準。仍不計算報酬或合併評分。

## 私有品質報告與逐規則分母

每個研究版本庫可重播一份 `alert-quality-1` 報告。以下範例讀取截至指定時間已保存的版本。請以實際目錄與截止時間執行。

```bash
uv run --locked python -m local.alert_quality \
  --root local/private/research-runs \
  --as-of 2026-11-19T03:00:00Z \
  --output local/private/alert-quality/report-001.json
```

CLI 先稽核整個版本庫與最新版本指標，最多讀 50 個版本及 256 MiB。有壞檔時會報錯。JSON 寫在研究庫以外的私有位置，上限 32 MiB。同內容可重跑，不同內容須使用新檔名。

| 報告欄位 | 核對方式 |
| --- | --- |
| `inputs` | 以 run ID 查 `known_at`、`completed_at`、選取範圍、封存報告 SHA256 與事實範圍。超過報告截止、或當時未開啟提醒的 run 各自有原因。 |
| `rules` | 六條規則各有 `saved`（每次保存）和 `first_saved`（每個案例首次保存）的分母。四種狀態均列零值，`evaluable` 加總觸發與未觸發，`unavailable` 加總不足與不可比，`reasons` 說明原因。此表僅盤點案例數，不對不同門檻、尺度或來源的數值取平均。 |
| `definition_groups` | 依規則版本、該規則使用的設定、公式、閾值、單位、來源與數值定義分開計數。每一版完整設定另在 `inputs[run].config`。 |
| `cases[].captures` | 同股票、目標期別及定義的每次保存。可從 `check` 看公式、比較值、基準日期、所需筆數、原因、證據及原始 alert ID。期別或整組來源證據缺失時，每次保存獨立計數。 |
| `inputs[run].raw_sources` | 行情證據逐筆帶 `raw_sha256`。營收以 `check.evidence[].input_snapshot_sha256` 查正規化快照內同 `dataset_id` 的原始收據。舊版本缺收據時保留缺口。 |
| `inputs[run].revision_notices` | 查該版已保存的行情或月營收通知、對象、日期與目標雜湊，另可依通知雜湊／來源參考回看封存檔。缺少通知時無法判定發布者是否正式更正或撤回。 |

依 `completed_at` 排序保留首次保存。跨版本的 `change` 以同案例的前一筆保存為基準。`repeat` 表示規則證據相同；同日或同月的同一輸入數值變動標記 `value_revised`。只有證據時間、快照等不同時標記 `provenance_changed`；觀察日期集合或計算狀態改變也各有標記。同時保存的相異計算結果無法決定先後，CLI 會停止。新設定或來源列入另一個定義。報價單位 `source_reported` 保持原值。

可額外指定 `--calendar PATH` 讀已保存的市場日曆，並用可重複的 `--action-manifest PATH` 讀已保存的官方 11633 收據。每筆 `price_context` 只使用該 run 的 `known_at` 前已保存的日曆與已收的事件證據，列出提醒視窗中有開市旁證卻沒有觀察的日期、日曆衝突與未涵蓋天數。查缺口成因可接續使用[交易日完整性報告](CALENDAR_COVERAGE.md)。已知上櫃除權息落在首筆觀察日之後、末筆觀察日以前（含末日）時，列出市場、股票、日期及原始 CSV 列號。此旁證保留原規則結果，並列出分割、減資等完整區間仍未知的限制。[價格基準與 11633 適用範圍](PRICE_ACTION_REVIEW.md)

數學觸發僅表示越過當時設定。未還原的價差可能來自除權息，觀察資料漏日可能改變價量基準，晚到修訂也可能改變同一期間的結果。現有樣本沒有可用於認定誤報的獨立標籤。真實兩市場六版逐例對照、尚缺的行情筆數與營收期別記在[品質驗收票](../.scratch/m4-research-quality/issues/01-alert-quality.md)。
