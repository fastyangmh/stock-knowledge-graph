## Standards｜實作、相容性與操作

| 審查發現 | 修復及獨立可觀察行為 |
| --- | --- |
| 重抓舊檔會把它當最新版。通知觀察後重抓同一版本，也可能導致首次通知被拒。 | 依實際觀察時刻辨識原始及正規化紀錄兩個 hash。A、B、A 三次擷取在截止時分別查回 A、B、B。明示通知可引用 B，指定已被取代的 A 則拒絕。只有 A 的情況下，通知觀察後重抓 A 仍能追認其早先已取得的同一版本。 |
| 第一份待生效通知過早固定原值。 | T3 登錄、T5 生效的更正，T3 仍見 11.00，T4 一般更新見 11.25，T5 見 11.50。三份研究均通過 audit。待生效期間另選的一般觀察保留兩個 hash、觀察時間與取得方式，再算檔案 hash 後仍能檢出不符的 high。 |
| 累計原件可超過讀回上限。 | 使用預設 128 MiB、每份通知原件 19,400,001 bytes 的七份合成通知。舊程式接受第七份；修復後第七份在寫入新原件與 SQLite 之前拒絕，相同失敗輸入可重試；第六份仍可重登及重讀。另以較小界線逐項驗證新登錄列、登錄 JSON 與替代 CSV 的工作量。 |
| 圖譜、提醒及本地替代件的取得方式可和事實不同。 | 由通過行情正規化驗證的事實重建選用報告、完整行情節點及每一筆提醒引用。重新計算圖、manifest、alerts、個別提醒及報告的 hash 後，各自竄改 high、price_unit、recorded_at、引用單位、可得時間均被拒絕。所有檔案一致把替代檔改稱 HTTPS 下載亦被拒絕。 |
| 同時移除另一檔的撤回理由，仍可能通過整包稽核。 | 以兩檔同日的更正和撤回重播。同步自 facts 與報告移除第二檔的撤回後，audit 因該股當日缺乏事實或有效撤回失敗。完整涵蓋檢查適用於有宣告行情範圍的未裁剪事實，限所選當日，保留無行情研究、舊展示版及較早日期的既有涵蓋語意。 |
| 降版讀者會恢復顯示被撤回的一般行情，單備份 SQLite 會遺漏來源原件。 | 合成 SQLite backup 及完整快照樹移至新目錄後，新讀者重播撤回前後皆正確。同一資料庫的舊 latest view 仍選出該筆原價。操作文件補上首次升級、原件與 manifest、SHA256 清單、獨立還原目錄與回退版本的可用截止。[升級、備份與回復](MARKET_PRICES.md#升級備份與回復) |

## Spec｜逐條核對

| 規格要求 | 證據及界線 |
| --- | --- |
| 「區分原檔缺列、晚到舊檔與正式撤回」 | 新的 A／B／A 與重抓 A 案例與既有缺列、撤回、明示重發、衝突測試共同通過，保留首次保存事件的既有基準。行情庫保有歷次擷取列與原始快照。 |
| 「恢復狀態時檢查目標版本、通知、替代原件與適用範圍」 | 首次通知核對觀察時與登錄時的版本，後續按 parent、原件／紀錄 hash、定義與時序連接。未生效、有效、撤回、重新發布各時點均用已保存資料查回。研究稽核比對圖譜實際輸出的 OHLC、成交數量、金額、筆數、定義、來源及各時間，並比對提醒實際引用欄位。 |
| 「失敗保全舊成功版本與可重跑狀態」 | 登錄時先計入該股當日重播所需的新舊原件及登錄資料。預設預算重現案例驗到第七次失敗和第六次可重跑；跨日期或股票的整次研究仍依其查詢總預算決定能否執行。 |
| 「以原兩日真實資料在副本重讀」 | 原私有腳本在候選版本以相同腳本雜湊執行。兩市場各兩日的截止、原始 CSV SHA256、行情欄位、事實、提醒、舊 bundle 及首次事件詳見下表。正式行情通知原件繼續列為 `needs-info`。 |
